## What's Fixed in v1.8.1

### 🔧 Phone Number Validation (CRITICAL FIX)
**Problem**: Phone numbers marked as invalid even though correct details were entered

**Root Cause**: 
- Numbers saved as `+254712345678` (13 chars) after normalization
- Validation checked for exactly 10 digits
- Valid numbers were rejected

**Solution**:
- ✅ Now accepts BOTH formats: `07xxxxxxxx` AND `+254xxxxxxxxx`
- ✅ Validates correctly regardless of how number was saved
- ✅ Better error messages showing exact format expected
- ✅ No more "invalid phone number" errors for correct numbers

### 📍 Location vs Address (CLARIFIED)
**User Concern**: "I don't want to see addresses"

**Investigation Result**:
- ✅ No address field exists in the app
- ✅ Only `location` field (e.g., "Kitengela", "Athi River")
- ✅ All screens correctly display location names
- ✅ Text parser extracts location, not address

**If you're seeing address-like text**:
- Check what's being entered in the "Location" field
- Use dropdown locations (Kitengela, Athi River, etc.)
- Keep locations short, not full addresses

## Valid Phone Number Formats

### ✅ Accepted Formats:

**Format 1**: `07xxxxxxxx` (10 digits)
```
0712345678 ✅
0723456789 ✅
0734567890 ✅
```

**Format 2**: `01xxxxxxxx` (10 digits - Landlines)
```
0112345678 ✅
0123456789 ✅
```

**Format 3**: `+254xxxxxxxxx` (13 characters)
```
+254712345678 ✅
+254723456789 ✅
```

### ❌ Invalid Formats:
```
712345678        ❌ Missing leading 0 or +254
07123456         ❌ Too short
071234567890     ❌ Too long
0812345678       ❌ Starts with 08 (not valid)
0712 345 678     ✅ Spaces OK (removed automatically)
```
