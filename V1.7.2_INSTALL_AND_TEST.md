### Issue 1: Database Not Loading (All Screens Slow)
**Symptoms:**
- Reports overview section not loading
- Members tab loading slowly
- Settings not opening
- No improvement from offline-first architecture

**Root Cause:** The background sync service may be crashing on startup, preventing the app from initializing properly.

**Debug Steps:**
1. Open the app
2. Immediately run: `adb logcat | findstr "BackgroundSyncService"`
3. Look for:
   - "BackgroundSyncService: Starting..."
   - "BackgroundSyncService: Started successfully"
   - Any error messages

**Possible Fixes Needed:**
- May need to disable background sync entirely if it's causing crashes
- Or increase delay to 10+ seconds
- Or check if database initialization is failing

### Issue 2: Scanner Still Detects Only 1 Member (Not 38)
**Symptoms:**
- Scanning attendance sheet with 38 attendees
- Only 1 attendee detected

**Root Cause:** Enhanced OCR extraction logic doesn't match the format of your attendance sheets.

**Debug Steps:**
1. Scan an attendance sheet
2. Run: `adb logcat | findstr "ENHANCED OCR"`
3. Look for debug output showing:
   - Total blocks found
   - Full text preview
   - Lines processed
   - Phone numbers found
   - Total attendees extracted

**What the Debug Output Will Show:**
```
=== ENHANCED OCR DEBUG ===
Total blocks: 5
Full text length: 1234
Full text preview: [first 200 chars of recognized text]
Processing 38 lines for table format...
Line 0: Found phone 0712345678 in: John Doe 0712345678 Nairobi
  -> Extracted: John Doe | 0712345678 | Nairobi
...
Strategy 1 (blocks): Found 35 attendees
Strategy 2 (table): Found 3 new attendees
Total attendees found: 38
=== END DEBUG ===
```

**If Output Shows "Total attendees found: 1":**
- The text format doesn't match our extraction patterns
- Need to see the "Full text preview" to understand the actual format
- May need to adjust regex patterns or parsing logic
